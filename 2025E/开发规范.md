# 工程环境配置部分

统一使用STM32CubeMX进行配置，在每次初始配置之前修改`.ioc`文件名称为工程名称再进行generate，保证后续生成工程名称正确

> 是否正确可以看生成的MDK-ARM文件夹下.uxproj文件名是否为所需工程名

- 若使用**STM32拓展板**，则直接复制Templete/STM_Tool作为模版工程使用

- 若使用**STM32核心板**，则复制Templete/Templete_STM32作为模版工程使用

  > 复制时需要修改文件夹名称和`ioc`文件名

打开一个引脚使用时，第一步就是在README文档中写对应名称与引脚的对应关系，并在CubeMX右侧面板中右键引脚修改`USER LABEL`为对应使用名。如：PB6 ------> I2C1_SCL     PB7 ------> I2C1_SDA



# 程序库设计与导入部分

首先将程序库所调用的头文件（如`外设.h`,`外设_uart.h`,`string.h`）全部放在Core/Inc/下的`AllHeader.h`文件中（需要自建），并在引用之前写好注释，如”//JY61P驱动头文件“。

- 若程序库是关于外设配置，则将程序库文件全部打包放在`Drivers/BSP/外设名`文件夹下

- 若程序库是关于主程序设计，则将程序库文件全部打包放在`Drivers/程序名`文件夹下

在Keil中，需要用正确的路径来进行库文件导入与Include Path，如`Drivers/BSP/外设名`，不要缺少BSP，也注意大小写！



# 文件的命名原则

**驼峰命名法**，每一个单词的首字母大写，其余小写，条件允许情况下单词中间用下划线隔开

**避免过长命名！**一般以3～10字符为宜

模版工程前面要加`Template`前缀，如`Template_ATX601`



# 从头开始设计配置一个外设

1. 复制单片机模版工程到`Peripheral Devices`文件夹下，修改文件夹名，打开CubeMX，修改`.ioc`文件名称为工程名称，进行generate
2. 在CubeMX中配置对应引脚和功能，再次generate
3. 在Keil中进行库文件导入，再编写主程序，使外设功能可被正常使用
4. 撰写README文档，说明外设的使用规范
5. 全部调试无误后，在文件夹名后面加上“(done)"，表示外设配置完成，可正常使用

### 注意

1. 编写主程序时，要根据实际情况修改库函数，使得可以从主程序**简洁、规范**地调用外设。比如JY61P陀螺仪需要在一开始使能中断并接收帧头，那么编写的库函数需要包括**对应串口**，而在主程序中只需写一句`JY61P_Init(&huart1);`即可。
2. 在写库函数时，多利用**传参**和**宏定义**的方式去定义在不同工程环境下可能会变化的变量，如**通讯串口**，**波特率**，**巡线速度**，**激光笔类型**等等，方便后续进行一键修改
3. 撰写README文档需要按照规范来：**范例可见Peripheral Devices/OLED_Screen(done)/README.md**，要求包含**工程配置，接线、供电，需要的库文件，`main.c`及`AllHeader.h`文件代码**（代码要求从`    /* USER CODE BEGIN 2 */`类似的用户代码起始行开始复制，到终止行结束，便于移植）

# 关于Keil使用

在每一次初始generate生成keil工程或从git上pull一个新工程时，需要进行如下操作：

1. Edit --> Configuration --> Editor --> Encoding 调整为GB2312编码
2. 打开魔法棒 
   - Target 勾选`Use MicroLIB`（轻量化编译库），更改ARM Compiler为`V6.31`或更高
   - Output 勾选`Create HEX File`和`Browse Information`
   - C/C++ --> Optimization 选择`Level 0(-O0)`，再添加`Include Paths`所需头文件
   - Debug --> Use 选择`ST-Link Debugger`，在Settings中的Flash DownLoad下选择`Reset and run`
